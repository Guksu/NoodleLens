# 권한과 데이터 처리

## 권한

| 권한 | 용도 | 없으면 |
|---|---|---|
| `sidePanel` | 사이드 패널 UI | 확장 프로그램을 쓸 수 없음 |
| `activeTab` | 사용자가 툴바 아이콘을 누른 탭에만 일시적으로 접근(요소 선택 스크립트 주입, 탭 제목·주소 표시) | 요소 선택 불가 |
| `scripting` | 위 탭에 content script를 필요할 때만 주입 | 요소 선택 불가 |
| `storage` | 설정, '브라우저를 닫을 때까지만' 보관하는 API 키(`chrome.storage.session`) | 설정 저장 불가 |
| `host_permissions`: `https://api.openai.com/*`, `https://api.anthropic.com/*` | 제공자 API 호출과 **오류 응답 읽기**. OpenAI는 잘못된 키 등의 오류 응답에 CORS 헤더를 붙이지 않아(2026-10-06 실측) 이 권한 없이는 오류를 구분해 안내할 수 없다 | 일부 오류가 '네트워크 실패'로 보임 |
| `optional_host_permissions`: `https://*/*`, `http://*/*` | 사용자가 설정에서 켤 때만 요청. 탭마다 아이콘을 누르지 않고 바로 선택 | 기본 동작(activeTab) 유지 |

- content script를 모든 페이지에 미리 넣지 않는다(`content_scripts` 선언 없음).
- 원격 코드를 불러오지 않는다. 확장 프로그램 페이지 CSP는 `script-src 'self'`, `connect-src`는 두 API로 제한한다.
- `chrome.storage.local`·`session`은 확장 프로그램 페이지와 service worker에서만 읽을 수 있게 접근 수준을 `TRUSTED_CONTEXTS`로 둔다.

## 수집하는 것과 하지 않는 것

| 수집함(요소를 선택할 때) | 수집하지 않음 |
|---|---|
| 선택한 요소와 조상·자식·형제·넘침 후보 요소의 태그, id, class(최대 8개), 허용 목록 속성 | 입력 요소의 값, 비밀번호 칸, `contenteditable` 영역의 글 |
| 글 앞부분(대상 300자, 그 밖 80자) | 쿠키, localStorage 등 페이지 저장소 |
| computed style 일부, 크기·위치·스크롤 값 | `data-*`, `value`, `name` 등 허용 목록 밖 속성 |
| 페이지 제목, 주소(origin + 경로, 쿼리는 키만) | URL의 쿼리 값, 해시, 사용자 정보 |
| 뷰포트 크기, 스크롤 위치 | 스크린샷(MVP에 없음) |

## 어디로 가는가
- **선택만 하면** 패널 메모리에만 있다.
- **질문을 보내면** 질문과 그 스냅샷 텍스트가 사용자가 고른 제공자(OpenAI 또는 Anthropic) API로 사용자의 키와 함께 전송된다. 보내기 전에 '수집 내용'에서 전송 텍스트를 그대로 보고 글·속성·주소·제목·개별 요소를 뺄 수 있다(대상 요소는 뺄 수 없음).
- NoodleLens 개발자 서버는 없다. 분석 도구·광고·텔레메트리 요청도 없다.
- OpenAI 요청은 `store: false`로 보내 응답 상태를 OpenAI에 저장하지 않게 한다. 각 제공자의 API 데이터 보존·학습 정책은 제공자 약관을 따른다(두 회사 모두 API 데이터는 기본적으로 학습에 쓰지 않는다고 밝힘).

## 보관과 삭제

| 데이터 | 보관 위치 | 삭제 |
|---|---|---|
| 대화·답변 | 확장 프로그램 origin IndexedDB `noodlelens` | 기록에서 대화별 삭제, 기록·설정에서 전체 삭제 |
| 보낸 스냅샷 원문 | 같은 DB `snapshots` (대화와 연결) | **대화를 지우면 함께 삭제** |
| API 키(이 기기) | 별도 IndexedDB `noodlelens-secrets`, AES-GCM 암호화. 암호화 키는 내보낼 수 없는 CryptoKey | 설정 > 키 삭제 |
| API 키(세션) | `chrome.storage.session`(메모리) | 브라우저를 닫거나 확장 프로그램을 다시 로드하면 사라짐 |
| 설정·동의 시각 | `chrome.storage.local` | 확장 프로그램 삭제 시 |

- 암호화는 디스크에 키가 평문으로 남지 않게 하는 정도의 보호이며, 같은 브라우저 프로필에 접근할 수 있는 사람이나 악성 프로그램까지 막지는 못한다. 전용 키를 만들고 지출 한도와 만료일을 걸어 두기를 권장한다.
- 키는 content script·페이지 DOM·로그로 보내지 않는다. 화면에는 끝 4자리만 보인다. 제공자 오류 메시지에 키 일부가 섞여 오면 가린다.
- 확장 프로그램 origin 저장소는 브라우저의 '인터넷 사용 기록 삭제'로 지워지지 않는다. 확장 프로그램을 삭제하면 함께 지워진다.

## 첫 실행 동의
처음 열면 위 내용을 요약해 보여 주고, 사용자가 '이해했고 동의합니다'를 눌러야 요소 선택과 질문을 쓸 수 있다(Chrome 웹 스토어의 눈에 띄는 고지·동의 요구 대응).

## Chrome 웹 스토어에 올릴 때 확인할 것(미완료)
- 개인정보처리방침 URL과 Limited Use 준수 문구 게시
- 대시보드 개인정보 탭: 단일 목적, 권한별 사유(위 표), 원격 코드 없음, 데이터 유형(인증 정보 = API 키, 웹사이트 콘텐츠 = 스냅샷)
- 저장 시 암호화 요구(사용자 데이터 FAQ)를 심사에서 어떻게 보는지는 확인하지 못함
