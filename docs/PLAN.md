# 개발 계획과 범위

## 목표
웹 UI를 개발·점검하는 프론트엔드 개발자가 페이지의 특정 요소를 골라 "왜 이렇게 보이는지"를 묻고,
실제 DOM·computed style·크기 측정값을 근거로 원인과 최소 수정안, 확인 방법을 받는다.
새 기능을 늘리기보다 **요소 선택 → 근거 수집 → 질문 → 근거 있는 답변 → 근거 강조** 흐름 하나를 안정적으로 만든다.

## 단계와 진행 상태

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 작업 위치·관례 확인, 저장소 생성 | 완료 (`Guksu/NoodleLens`, public) |
| 2 | 모델 연결 방식 비교, 연결 방식 확정 | 완료 — 사용자 API 키(BYOK) 확정 ([CONNECTION.md](CONNECTION.md)) |

| 4 | 실제 모델 연결과 분석 | 구현 완료. 실제 서버 401 처리 확인. **유효한 키로 응답을 받은 검증은 미완료**(키 대기) |
| 5 | Sider를 참고한 UI 정리 | 완료 ([DESIGN.md](DESIGN.md#12-ui-sider-참고)) |

## MVP 범위
- 문제 유형: 가로 넘침과 불필요한 스크롤, 텍스트 말줄임 실패, Flex/Grid 정렬·크기 문제(이미지 넘침 포함)
- 툴바 아이콘으로 사이드 패널 열기, 클릭한 탭에 activeTab
- 요소 선택 모드(hover 강조, 클릭 선택, Esc 취소, ↑ 부모 선택, 링크 이동 방지, 정리)
- 구조화된 스냅샷 수집(상한·생략 기록, 민감 정보 제외), 전송 전 미리보기·제외
- 규칙 기반 기본 검사
- GPT·Claude 선택(대화별 제공자 고정), 스트리밍, 중단, 명시적 재시도, 오류 구분
- 근거 식별자 검증과 클릭 시 페이지 강조, 사라진 요소·이동한 페이지 안내
- 대화 목록·새 분석·삭제, 로컬 저장, 패널 닫기·다시 열기 복원
- 첫 실행 데이터 고지·동의, API 키 암호화 저장 또는 세션 보관

## 초기 범위에서 제외한 것
- 페이지 전체 자동 감사, 모든 종류의 접근성·성능 진단
- React 상태·리렌더링 원인 분석, 소스 저장소 연결과 실제 파일 수정
- AI가 만든 JavaScript 자동 실행, 여러 에이전트 구성, Figma 연동
- 자체 서버·벡터 DB
- 스크린샷 첨부, 임시 CSS 적용 미리보기, 수정 전후 재측정(아래 후속 단계)
- ChatGPT 플랜 로그인(Sign in with ChatGPT), Claude 구독 로그인
- iframe 내부 문서·closed shadow root 내부 선택

## 후속 개선 우선순위
1. **실제 모델 평가 완료** — `.env.local`에 키를 넣고 `npm run eval`로 dev·heldout 사례를 두 제공자에서 실행, 결과를 EVALUATION.md에 기록. 결과를 보고 프롬프트를 바꾸면 heldout 결과와 분리해 기록한다.
2. **선택 영역 스크린샷 첨부** — `tabs.captureVisibleTab`(activeTab 필요)으로 DOM 수집과 같은 시점의 화면을 잘라 첨부. 전송 범위 확인 UI, 리사이즈 기준(긴 변 1568px 이하 등) 결정.
3. **임시 CSS 수정 미리보기** — 사용자 승인 후 허용한 속성만 대상 요소에 적용하고 원상 복구 제공. 서버·저장소 소스가 바뀌는 것처럼 표현하지 않는다. 임의 JavaScript 실행으로 넓히지 않는다.
4. **수정 전후 재측정** — 넘침·크기·위치 측정값을 비교하고, 화면상 증상이 사라진 것과 근본 원인 해결을 구분해 보여 준다(평가 도구의 측정 함수를 재사용).
5. 브랜드 Chrome(154)에서 수동 설치 점검 체크리스트 실행(자동화는 Chrome for Testing에서 함).
6. 같은 출처 iframe 지원, hover 상태 유지 수집 옵션.
7. Chrome 웹 스토어 배포 준비(개인정보처리방침, 대시보드 개인정보 탭).
8. ChatGPT 플랜 연결 재검토(조건은 CONNECTION.md).
